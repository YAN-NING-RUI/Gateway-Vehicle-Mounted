## 2. 硬件连接

```
H743 PB9 (FDCAN1_TX) ──→ 收发器模块 TXD
H743 PB8 (FDCAN1_RX) ←── 收发器模块 RXD
收发器 CANH/CANL ──→ 200U（ZQWL-UCANFD-200U）CAN0
```

- 收发器模块型号待确认（丝印未知），供电 VCC / VIO / STB 接法待核对；
- 200U 为电气隔离型，CAN0 通道，500 kbit/s；
- 终端：模块与 200U 各一组 120 Ω（目标 60 Ω）；
- 逻辑分析仪：正点原子 ATK-Logic DL16，探头接 PB9、PB8，GND 与板共地。

## 4. 软件实现

- `CanTask`：CubeMX 创建（优先级 AboveNormal，栈 2048 B），独占 FDCAN1；
- `S2_CanInit()`：配过滤器 → 配全局过滤（未匹配帧/远程帧全部拒绝）→ `HAL_FDCAN_Start()`，每步记录 `g_s2.init_step`；
- `S2_Transmit(id, data)`：
  1. 提交 `HAL_FDCAN_AddMessageToTxFifoQ()`，成功后取 `HAL_FDCAN_GetLatestTxFifoQRequestBuffer()`；
  2. 等 `TXBTO`，预算 20 tick（约 20 ms）；
  3. 超时后置 `tx_timeout`，若 `TXBRP` 仍挂起则 `HAL_FDCAN_AbortTxRequest()`，再等 20 tick 观察；
  4. 取消一直清不掉 → `g_s2.tx_stuck = 1`，拒绝后续提交；
- 调试变量集中在 `g_s2`（`s2_diag_t`，11 个字段）；
- **当前为调试版本：CanTask 每 100 ms 连续发送一帧 `0x321`**（载荷 `53 32 41 00 00 00 00 00`）。

## 5. 现象与证据

### 5.1 调试变量

| 变量 | 值 | 含义 |
|---|---|---|
| `task_created` | 1 | CanTask 已运行 |
| `init_step` / `init_ok` | 4 / 1 | 过滤器、全局过滤、启动全部成功 |
| `tx_submitted` | 增长 | 帧成功进入 Tx FIFO |
| `tx_confirmed` | **0** | TXBTO 从未置位 |
| `tx_timeout` | 增长 | 每次都在 20 ms 后判超时 |
| `tx_slot_mask` | 1 | 使用槽 0 |

### 5.2 寄存器快照

| 寄存器 | 值 | 解码 |
|---|---|---|
| CCCR | `0x1040` | DAR=1（一次性发送）、PXD=1、INIT=0、TEST=0 |
| ECR | `0x1100` | TEC=0x00、REC=0x11（17）（可能被列宽截断，待复核完整 32 位） |
| PSR | `0x76d` | **LEC=5（Bit0 错误）**、ACT=1（Idle）、EP=1（Error Passive）、EW=1、BO=0 |

### 5.2.1 连续运行数秒后的 Tx 缓冲状态

| 寄存器 | 值 | 含义 |
|---|---|---|
| TXBCR | `0x0` | 没有未完成的取消请求 |
| TXBTO | `0x0` | **没有任何一次发送成功** |
| TXBCF | `0xF` | 4 个 Tx 缓冲的“取消完成（Cancellation Finished）”全部置位 |

结合 DAR=1（一次性发送）：发送失败时硬件直接放弃该帧并置 `TXBCF`，不会置 `TXBTO`。因此 `TXBTO=0 + TXBCF=0xF` 表示**连续多次尝试全部失败**，与 `g_s2.tx_confirmed=0`、`PSR.LEC=5` 相互印证。

补充：`TXBCF` 置位后会保持，不主动清除就无法区分“本次失败”与“上次残留”；这也是当前代码只等 `TXBTO` 会白等 20 ms 的原因。

### 5.3 逻辑分析仪波形

| 场景 | 波形 | 说明 |
|---|---|---|
| 断开 MCU 与收发器连接 | PB9 有一簇约 30–40 µs 的波形后转高 | 帧被提前中止 |
| 接上收发器 | PB9 只有**一个约 1.65 µs 的低脉冲**，之后全高 | 仅发出 SOF 就中止 |
| 两种场景 | **PB8（RXD）始终为高** | 收发器没有把 TX 反映回 RX |

**关键推算**：1 位 = 2.0 µs，采样点 80% = 1.6 µs；实测低脉冲 1.65 µs，正好是“发到采样点被判错就中止”。

### 5.4 200U 侧

- 用工具的「波特率探测」（CAN 模式、CAN0、SJW 1TQ、TSEG1 12TQ、TSEG2 3TQ）扫描：**全部 Not match**；
- 该测试时期间存在“收发器链路被断开”的可能，结论待复测。

## 6. 已排除的假设

| 假设 | 排除依据 |
|---|---|
| MCU 没发 | PB9 上有波形，帧头结构正常 |
| 位时序/时钟错误 | PB9 上位宽实测约 2.0 µs，对应 500 kbit/s |
| FDCAN 没启动 | `init_step=4`、`init_ok=1`，CCCR.INIT=0 |
| 软件卡死 | `task_alive` 持续增长，LED 心跳正常 |
| 帧被过滤器挡住 | 过滤器只影响接收，与发送无关 |

## 7. 当前最可能的原因（排序）

1. **收发器模块未正常工作**：供电（部分模块需 5 V）、VIO、STB/EN 电平、TXD/RXD 接反，或模块损坏；
2. **CANH/CANL 短路或接错**：总线始终呈隐性，控制器读回与自己发送相反的位（Bit0 错误）；
3. **Bus-off 叠加效应**：DAR=1 时每次失败 TEC+8，约 32 次（≈4 s）后进入 Bus-off，之后完全不再发送——这解释了“有时能抓到脉冲、过一会儿完全静默”。

**证据强化**：运行数秒后 `TXBCR=0 / TXBTO=0 / TXBCF=0xF`，说明 4 个发送缓冲的每一次尝试都被硬件以“放弃”结束，从未成功——与“RX 回读不到显性位（Bit0 错误）”完全一致，可排除偶发干扰，属于**持续性物理层问题**。

## 9. 想请对方重点判断的问题

1. 只有 **LEC=5（Bit0）**、没有 ACK 错误，是否足以判定“RX 回读路径断开”，而不是“总线上没有其他节点”？
2. DAR=1（一次性发送）下，帧在第一个采样点判错即中止，是否会产生 1.65 µs 的窄脉冲（即 SOF 未发完）？这与观察是否一致？
3. TJA1050 / SN65HVD230 / TJA1042 这类模块，3.3 V MCU 直接驱动 TXD、VCC 接 5 V、STB 悬空，是否会导致“TXD 有波形但 RXD 无回显”？
4. 是否存在“模块 TXD 与 RXD 接反”时仍能看到 TXD 波形的可能（即接反不一定会立刻损坏）？
5. 除硬件外，是否还有软件层面的原因会让 RX 读回与 TX 相反（例如 GPIO 复用未生效、PB8 被其他功能占用）？
6. `TXBCF` 在 DAR=1 失败后会保持置位：是否应在每次提交前写 1 清除，并以“`TXBTO` 先到 = 成功 / `TXBCF` 先到 = 失败”作为判据，避免固定等待 20 ms？
