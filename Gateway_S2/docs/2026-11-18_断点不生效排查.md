# 断点不生效排查记录（STM32CubeIDE / ST-LINK）

- **日期**：2026-11-18
- **工程**：`C:\Users\28784\Documents\ChatGPT\CAN_GATEWAY\H743_FreeRTOS_Bringup`
- **阶段**：S2-A（FDCAN1 Normal 模式）
- **环境**：STM32CubeIDE 1.17.0 / CubeH7 V1.12.1 / ST-LINK V2

## 1. 现象

- 在 `main()` 与 `main.c:960`（`g_heartbeat++`）下断点，程序不停，LED 持续闪烁；
- 但手动点 **Suspend** 能让 CPU 停住，Debug 视图能看到调用栈；
- Console 无报错，程序确实已在运行（`g_heartbeat` 在增长）。

## 2. 判断

**Suspend 有效 ⇒ 连接与下载正常，CPU 在调试器控制之下。**

因此问题不在调试链路，而在**断点没有被安装或没有绑定到地址**：

| 可能 | 表现 |
|---|---|
| 断点在会话建立前添加 | 新会话未把它们写进目标 |
| 旧启动配置失效 | `.launch` 仍绑定旧工作区 / 旧构建配置 ID |
| 镜像与 ELF 不匹配 | 断点图标为空心（未绑定） |

## 3. 解决步骤（实际执行）

1. 终止所有调试会话，Debug 视图清空；
2. `Project → Clean`，再 Build（确认 0 error）；
3. `Run → Debug Configurations`：删除旧的 `H743_FreeRTOS_Bringup` 配置；
4. 双击 `STM32 C/C++ Application` 新建配置；
5. **Main 页**：Project = `H743_FreeRTOS_Bringup`；C/C++ Application = `Debug/H743_FreeRTOS_Bringup.elf`；
6. **Debugger 页**：Interface = `SWD`；Probe = `ST-LINK`；Reset = `Software system reset`（NRST 未接时不要选 Hardware reset）；
7. **Startup 页**：勾选 `Set breakpoint at: main`；
8. `Apply → Debug`，等程序停在 `main()` 后再下断点。

## 4. 验证

- 程序能停在 `main()`；
- 重新添加的断点在运行后能命中；
- Console 出现 `Downloading` / `Verify` / `Breakpoint at main`。

## 5. 预防

1. 调试固定顺序：**先 Debug 启动 → 停在 main → 再下断点**；
2. 工程跨路径或跨工作区迁移后，**必须重建启动配置**（旧 `.launch` 不会自动跟随）；
3. 遇到"断点不生效"先按此顺序判定：
   - Suspend 能否停住 → 区分"控制权问题"与"断点问题"；
   - 检查 `Skip All Breakpoints`（工具栏斜杠图标）；
   - 看断点图标：实心=已绑定，空心=镜像不匹配；
   - 看 Startup 页 `Set breakpoint at: main` 是否勾选。
